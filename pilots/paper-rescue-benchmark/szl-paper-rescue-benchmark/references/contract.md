# Paper rescue pilot contract

The CLI takes three explicitly selected local files: `--pdf`, `--records`, and `--gold`. It reads at most 128 MiB of PDF bytes and 1,000,000 bytes from each UTF-8 JSON input. The PDF must begin `%PDF-`; the tool is **not** a PDF parser and does not verify its true page count. JSON duplicate keys, unknown fields, non-finite numbers, malformed boxes, and undeclared candidate IDs fail closed. The candidate list has 0–1,000 items; the reference list has 1–1,000 items. IDs are unique and match `[A-Za-z][A-Za-z0-9_-]{0,63}`. SHA-256 values are lowercase hex.

`records.json` has exactly `schema`, `pdf_sha256`, `declared_pages`, `rights`, `pipeline`, `items`. Schema is `szl.paper-rescue.records.v1`. `declared_pages` is an operator assertion from 1 to 10,000. `rights` has exactly `basis` (`operator-created`, `public-domain`, `licensed`, or `permission-granted`), `evidence_uri`, `attestation_id`, `local_processing_authorized: true`, and `contains_patient_data: false`. This gate requires an explicit assertion; the code cannot authenticate a license or detect undisclosed patient data. `pipeline` has exactly `name`, `version`, `ocr_engine`, and `remote_services_used: false`; this is recorded provenance, not proof of the pipeline that actually ran.

`gold.json` has exactly `schema`, `pdf_sha256`, `declared_pages`, `annotation_basis`, `reviewer_count`, `items`. Schema is `szl.paper-rescue.gold.v1`. The PDF hash and declared page count must match the candidate record. `annotation_basis` is `SYNTHETIC_FIXTURE` with zero reviewers or `INDEPENDENT_HUMAN_ADJUDICATED` with at least two reviewers. Both are declarations, not identity or independence checks. Keep this file sealed from the extraction and tuning process.

Each candidate and reference item has an `id`, `kind` (`cell` or `caption`), and `status`. A `LOCATED` item also has 1-based `page`, normalized top-left `bbox: [x0,y0,x1,y1]` with finite coordinates in `[0,1]` and positive area, and complete `text`. A located `cell` additionally requires nonempty `row_header`, `column_header`, and `unit`; use an explicit notation such as `dimensionless` where appropriate. A located `caption` does not carry cell metadata. An `UNRESOLVED` item has only `id`, `kind`, `status`, and a nonempty `reason`; it must not silently carry a partial location or value. Reference `UNRESOLVED` items can represent negative or genuinely unreadable cases.

The primary metric is `counts.matched_reference / denominator`, where the denominator is every reference item. Missing candidates and `UNRESOLVED` candidates remain in it. Matching requires the same kind, page, complete text and cell metadata, plus bounding-box intersection-over-union of at least 0.5 with the declared reference. A located record for a reference `UNRESOLVED` item is `UNSUPPORTED_LOCATED_CLAIM`. Page/box disagreement is `REFERENCE_LOCATOR_MISMATCH`; field disagreement is `REFERENCE_CONTENT_MISMATCH`. These codes report disagreement with the supplied reference, **not** proven falsehood in the PDF. A reference item itself may be erroneous; humans must inspect the original page.

The report records SHA-256 of the exact PDF, record JSON, and gold JSON bytes, counts and per-ID codes without repeating source text. It explicitly sets rights, human adjudication, visual truth, actual PDF page count, scientific truth, and clinical qualification to unverified/false. A 0 exit is never a pass for a research claim or production workflow. For any real evaluation, preselect rights-cleared documents, freeze a held-out split by report family, require two independent visual annotators and adjudicate disagreements, and report uncertainty, abstentions, false reference matches, latency and cost. The current NASA native-extraction pilot remains unscored.
